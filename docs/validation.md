# Executed validation — 2026-09-16

This is a local prototype and a candidate behavioral baseline. It is not a
production cutover, proof of every provider/client, or an approved golden standard.

## Runtime and deterministic checks

- Python 3.13.14, Pydantic 2.13.5, official Neo4j Python driver 6.3.1.
- Dedicated local Neo4j 5.26.30 Community container `graph-memory-dev`, with its
  own volume and loopback ports 17687/17474. Existing databases were not reused.
  Port 17687 has since become the live personal graph. Tests now run against the
  disposable database from `compose.test.yaml` on 37687.
- 36 Python tests passed against real Neo4j, including HTTP wire handling,
  concurrent idempotent commits, temporal ordering/conflicts, missing-source
  exclusion, automatic structural repair, document dates, append-only feed
  cursors, restart catch-up, worker retry backoff, dreams, and revision promotion.
- All 284 existing TypeScript tests passed. The new runtime does not load that
  plugin or use its dependencies.
- Ruff checks/formatting passed; wheel and source distribution built. The wheel
  includes the fixed eval fixtures and runner. CI gained an isolated Neo4j job.

Commands are in [CONTRIBUTING.md](../CONTRIBUTING.md). Generated local evidence
lives under ignored `.local/`; these files can contain private source excerpts.

## Luna extraction and dreaming

Codex CLI 0.154.0 was used with `gpt-5.6-luna` and the then-selected default, `medium`. The pinned six-case
suite passed twice: **12/12 model cases**. Each case uses a new isolated namespace.
The Atlas case includes actual Luna dreaming, supported-insight promotion, and
checks that the original facts stay unchanged. Engine source and suite hashes
were unchanged during the passing run.

See [candidate report](../evals/baselines/candidate.json). The report records exact
engine/suite hashes, outputs, checks, model, and effort. It remains explicitly
unapproved; expectations are never regenerated from model results.

Validation caught invalid relationship endpoints, unsupported dream citations,
incomplete extraction, undated activity claims, and identity collisions. Invalid
candidates were rejected before publication. Corrections retained the original
expected outcomes; the complete suite was then rerun. Unknown event times remain
uncertain, and same-named entities with distinct qualified keys stay separate.

The [effort comparison](../evals/effort-study.md) includes separate high/medium
trials and earlier Extra High failures. The exported JSON Schema now expresses
the same unknown-event-time constraint as runtime validation. A new deterministic
contract test protects that alignment; golden expected outcomes were not relaxed.

## Real Claude native-memory versus MCP comparison

The final default-medium engine passed the focused Atlas PostgreSQL migration
case in two fresh Claude sessions. Both used the same redacted memory snapshot:
the original index and relevant workstream note. The primary answer model was
`claude-sonnet-5` in both arms, as recorded by Claude CLI's model usage.

The native-memory arm successfully read the source note. The native-memory-off
arm used only the scoped retrieval MCP tools, including `memory_recall`,
`memory_latest`, and `memory_pending`; file tools were unavailable. Both returned
the expected paused migration status, did not claim confirmed deployment or live
verification, and quoted exact original evidence. The graph's document-date
provenance was distinguished from current external state. Session IDs differed,
the engine hash stayed unchanged, and the temporary graph was cleaned up.

The same-engine report is bound into the candidate baseline by digest. See the
[public aggregate](../evals/baselines/claude-ab-summary.json). Private full traces
are `.local/final-medium-claude-ab.json`; they are not packaged or checked in.
This is a bounded known-answer comparison. No live production tools were supplied,
so it tests appropriate qualification, not the ability to perform a live production
check. Structured checks and reviewed traces do not certify every prose assertion
or establish general superiority over native memory.

## Real Claude and Codex bank trial

The original banks were read without modification. Initial import staged 843
unique source episodes in `sandbox:rob-memory-20260916`; a later timestamped
Codex transcript sample added one more. Three episodes were extracted, totaling
36 facts, and a separate Luna dream produced two supported insights and three
observations. Most of that bank remains pending; staging is not extraction.

The sources covered Atlas workstream notes, a September 14 deployment summary,
and actual timestamped Codex session messages. Undated source claims remained
uncertain in that early import. Fresh imports now also retain source filesystem
dates and expose undated facts as documented claims, without inventing event
or verification timestamps. Existing sandbox evidence was not backfilled.

Full-bank extraction and switching global Claude/Codex memory settings have not
been performed. The new runtime can be enabled through scoped client config.
